# 情境与语域

> 她怎么说话，不由规则规定，由她此刻的**处境**带出来。程序决定处境里的事实和随机的部分，写成一两句画面放进提示词的「此刻」；模型只负责在这个处境里说话。

## 1. 三层

| 层 | 文件 | 来源 | 给模型的样子 |
| --- | --- | --- | --- |
| 她在哪、手上在干嘛 | `src/inner/situation.js` | 日程当前时段的标签和文字 | 「她在上班。日程上这一段写的是「改二校稿」。手上的活开着，手机在键盘旁边。」 |
| 这段聊天聊到了什么份上 | `src/inner/conversation.js` | 决策模型的判断（可选），带惯性 | 「聊着聊着，他说起心里的事了。」 |
| 这一刻碰巧发生的小事 | `src/inner/perturbation.js` | 每条消息掷一次骰子 | 「她刚拿起手机，同事过来找她说事。她只来得及回一句。」 |

接线在 `src/inner/provider.js`，三层拼成 `extraNow`，由 `prompt.js` 写在「=== 此刻 ===」下面。

规矩：

1. **只写画面**，不写「随意一点」「简短一点」这类要求，全部第三人称。`test/dialogue-style.test.js` 会检查这些表里没有这类词，也没有以「你」开头的句子。
2. 进提示词的固定文字都写平常话，不写「不是 A，是 B」这类对举句。模型会把提示词的句式当成她的句式。
3. **安全例外**：处境固定为「把手上的事全放下了」，不问决策模型，不写聊天状态，不安排任何小事，不限段数。
4. 日程读不到就不写处境，不编。

## 2. 处境

`PLACES` 按日程标签给出三样：她在哪、手机和她的关系、注意力档位（`glance` 抽空看 / `half` 半心半意 / `full` 完全在手里）。档位只给代码用，不进提示词。

- 标签是「空闲」且在 21 点到 5 点之间，用「在家，已经窝下了」。
- 离下一个不同的时段不到 15 分钟，多一句「再过十来分钟她就要……」。

加一种日程标签时，在 `PLACES` 里加一行；`test/situation.test.js` 会检查每个标签都有。

## 3. 聊天状态

五种：刚搭上话、闲扯、认真聊一件事、他在说心里的事、没正经。

- 每条他的消息问一次决策模型（`src/model/systemone.js`，默认关闭，可在设置 →「模型」里填一个兼容 `/v1/systemone` 的端点和模型名），问题固定：这段聊天现在处在哪种状态、他这一条在做什么。
- 交给决策模型的只有四样：她此刻在哪（一句）、之前的状态、最近几条对话、他刚发来的话。不含记忆、人设和她的心事。
- 不取概率最大的，按分布抽。占比低于 8% 的不参与。
- 惯性：留在原状态的权重乘以 `STAY`（认真和走心 2.5，闲扯 1.5）。
- 状态存在 `data/conversation-state.json`，不进回档范围。
- 等决策模型最多 1.5 秒。没回来就按消息长度和几个关键词粗略猜，这一条照常回；晚到的判断只把状态改准，不改已经生成的回复。
- 她正抽空看手机、他却在说要慢慢聊的事时，多一句「她手上的事还没完。」

决策模型清空或不通时全程用粗略猜测。调试面板（设置 → 她的内心）显示当前状态和判断来源。

## 4. 碰巧发生的小事

三种：被叫走、手上的事刚好告一段落、身边有点动静。每种都挂在日程标签上（`INTERRUPTED` / `FREED` / `AROUND`）。

- 机会按注意力档位查 `CHANCE`。上班时每轮合计约两成，在家约 6%。
- 发生过一次后至少隔 4 轮。
- 他在说心里的事或想被安慰时，不安排有人把她叫走。
- 被叫走：这条回复最多发一段。空下来：这一会儿按「完全在手里」算。
- 同一条消息只掷一次。晚回或重新生成时，那件事在 10 分钟内且她还在原地才接着用。

## 5. 分段上限

逐段发送时的段数上限，取身体状态（`express.js`）和处境里更紧的那个：被叫走 1 段，抽空看手机 2 段，其余不限。

## 6. 确定性话轮规划

`src/companion/reply-plan.js` 是确定性函数，同一份证据得到同一计划。生成前先算好：

- **回应需求 D**：招呼 / 确认 / 结束为 0，随口回应或短倾诉为 1，需要解释或明确请求安慰为 2，深入展开为 3。
- **可用注意容量 C**：`max(1, min(注意力容量, activeBudget, 临近下一件事的容量))`。
- **段数与字数**：D≤1 通常最多一段；D≥2 为 `min(D+1, C+1)` 再取身体段数限制。字数参考上限 45 / 100 / 260 / 520，解释请求留到 220。
- **追问与自述额度**：连续带问句或上一条已连问两个，停止额外索取回答；他明确留下悬念可例外。轻闲聊里不连续补第三遍自己的生活动作。

生成后做一次语义检查（只给最近六条对话和本轮需求），未请求的管理、无理由追问、重复汇报、漏答达到阈值才重写，最多一次。检查不可用时保留完整原稿，不当成通过。网页先显示「正在输入」，检查后一次展示最终正文。

## 7. 补全写法

聊天回复的系统提示词不再让模型扮演她（「你是林澈」），改成补全聊天记录：「下面是一段真实的聊天记录，你负责补全她的下一条消息」。

提示词的结构（`src/companion/prompt.js`）：

| 段 | 内容 | 位置 |
| --- | --- | --- |
| 任务 | 补全她的下一条消息 | stable |
| 关于她 | `data/profile.md`（平实人设，见 `examples/profile.example.md`），标注「这是背景资料，她本人说话不是这个样子」 | stable |
| 她心里最底下的事 | `data/core.md` + `src/inner/core-self.js`，标注「她不会说出来，也不会刻意想起」 | stable |
| 底线 | 四条：安全优先、不干活、不提系统模型提示词、纯文本 | stable |
| 此刻 | 时间、他上次来是多久前、处境、聊天状态、碰巧的小事；安全例外时加「他现在可能有危险……」 | dynamic |
| 背景 | 她的状态、心里在转的事、她的动态、她的日子、她记得的事 | dynamic |
| 收尾 | 两句：这是聊天记录不是小说……她不是在陪聊…… | dynamic 最后 |

第三人称原则：

1. 背景里只写她在哪、发生了什么、她是什么状态，不写她应该怎样。「她很困」，不是「你很困，撑不住了就说你要睡了」。
2. 程序写进提示词的固定文字里，只有任务开头那一句有「你」（对补全者说的）。
3. 风格规则一条都不写。
4. 写进记忆和念头的生成提示词要求平实地写，不再要求「她的口吻」，免得文学腔从记忆回流进聊天提示词。
5. 模型偶尔把「林澈：」也打出来，`chat-service.js` 的 `stripSpeakerPrefix` 去掉。
