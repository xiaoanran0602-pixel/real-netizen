# 念头池内核施工思路

> 状态：**已施工（2026-10-10）**，与活人感内核并行，按 body-kernel.md 第 1.2 节的口径收紧。实现与偏差见文末「施工记录」。
> 一句话：她的内心是一个装着十几条念头的池子。池子自己运转，他的消息只是打断它。所有活人感是池子的副产品，不单独做变量。

---

## 0 先回答一个问题：是不是主模型前面加一个快的小模型

是，但要说清楚小模型干什么、不干什么。

小模型不抉择她说什么，不生成任何给他看的文字。它只干两件"分类"活：

1. 主模型调用前：给「他这条消息 × 池子里每条念头」打相关度，输出一组 0–1 的分数。一次调用，输入很短，输出是数字。
2. 聊天后（异步）：从这轮对话抽取新念头、标记哪些旧念头被闭合了。输出结构化 JSON。

池子的涨落、挤出、溢出、路由全是代码算术，零模型。主模型仍然只在原来那一处被调用，只是喂给它的提示词换了来源。

小模型超时或失败：第 1 件退化成"按强度取前 N 条"，第 2 件下次再补。任何时候都不能让小模型阻塞回复。

---

## 1 数据结构

一个 jsonl 文件 `thoughts.jsonl`，每行一条念头：

```json
{
  "id": "t_20261010_001",
  "content": "他说下周要搬家，还没说搬去哪",
  "strength": 72,
  "source": "him",
  "speakable": true,
  "avoid": false,
  "closes_on": "他提到搬家日期",
  "born": "2026-10-10T21:30:00+08:00",
  "last_touched": "2026-10-10T21:30:00+08:00",
  "decay": "open_loop"
}
```

字段说明：

| 字段 | 含义 | 取值 |
|---|---|---|
| content | 念头本身，用她的口吻写的一句话 | 自由文本，≤40字 |
| strength | 此刻在她脑子里占多大 | 0–100 |
| source | 来源 | `him` 他留下的 / `life` 她自己生活的 / `world` 外部世界的 / `infer` 她对他的推断 |
| speakable | 她会不会主动说出来 | true/false |
| avoid | 被碰到时是否回避（回避的念头被碰到不激活，反而涨） | true/false |
| closes_on | 闭合条件，自然语言，给小模型判断用 | 文本或 null（无闭合条件，只靠衰减） |
| decay | 衰减曲线类型 | 见 §2 |

池子容量：**15 条**。这是最重要的两个手感参数之一，见 §7。

## 2 三个函数

### 2.1 tick（每小时，纯代码）

对每条念头按 `decay` 类型调整 strength：

| decay 类型 | 行为 | 用于 |
|---|---|---|
| open_loop | 未闭合时每小时 +1，上限 95 | 没回音的话、没做完的事、等结果 |
| fade | 每小时 −2 | 一般的事、闭合后的念头 |
| slow_fade | 每天 −3 | 她对他的推断、不可说的事 |
| spike | 第一天 −10/小时，之后 fade | 突发情绪、被说重话 |

tick 之后：

- strength ≤ 5 的删除。
- 超过 15 条时，删掉 strength 最低的，直到 15 条。**她会真的忘事。**不做任何提醒。
- 调用 overflow（§2.3）。

tick 和他在不在完全无关。他三天不来，池子照样跑 72 次。

### 2.2 collide（他的消息进来，主模型调用前）

输入：他这条消息、池子全部念头。

步骤：

1. 小模型打相关度。提示词大意："下面是一个人此刻心里的一组念头，和她刚收到的一条消息。给每条念头打 0–1，表示这条消息会不会让她想起这个念头。只输出 JSON 数组。" 超时 800ms → 退化为按 strength 排序。
2. 分组：
   - **激活集**：相关度 ≥ 0.5 且 avoid=false。它们的 strength +5，last_touched 更新。
   - **回避命中**：相关度 ≥ 0.5 且 avoid=true。不进激活集，strength +10。他碰到了她不想说的东西，她那边压力涨了，但表面绕开。
   - **背景集**：相关度 < 0.5 但 strength ≥ 60。她脑子里正占着带宽的别的事。
3. 构造提示词注入块（§3）。
4. 主模型生成回复。
5. 回复后，这轮对话进入异步抽取（§2.4）。

### 2.3 overflow（strength 过阈值，纯代码）

tick 之后检查每条 strength ≥ 80 的念头：

- speakable=true：按 source 路由到出口
  - `him` → 候选主动消息。"他留下的事没有回音，她忍不住问一句"。这就是想念，不需要想念值。
  - `life` → 日程生成的素材 / 朋友圈候选。
  - `world` → 朋友圈候选。
  - 路由出去后 strength −30（说出来就轻了）。
- speakable=false：不能出去
  - 把 strength 的 20% 分给池子里 source 相同的其他念头（压抑的东西换出口，她会因为一件不能说的事对别的事反应变大）。
  - 若 strength ≥ 95 且当前有对话在进行：标记 `leak=true`，提示词里允许主模型"漏半句"。这是叔本华式出口，不需要单独做。

主动消息出口受现有的节流规则约束（夜间、当天上限）。但来由永远是池子里一条具体的念头，不是随机触发。

### 2.4 extract（聊天后，异步，小模型）

输入：这轮对话全文、池子当前内容。

小模型输出 JSON：

```json
{
  "new": [ { "content": "...", "source": "him|life|world|infer", "speakable": true, "avoid": false, "closes_on": "...", "decay": "open_loop" } ],
  "closed": [ "t_xxx", "t_yyy" ],
  "touched": [ "t_zzz" ]
}
```

规则写进小模型提示词：

- 他说的事实 → source=him，大多 speakable=true。
- 他对她说了重话 / 冷落 → source=him，speakable=false，decay=spike。她不会说，但它在。
- 她对他的判断（"他说不在乎的时候都在乎"）→ source=infer，speakable 视情况，decay=slow_fade。他反驳时降强度，不删除。她会坚持错误看法然后慢慢松动。
- 他推荐的东西 → source=him，closes_on="她看了/听了"，然后进日程素材。闭合时生成一条新念头带她的看法，source=life，speakable=true。他的痕迹在她那边走一圈回来。
- closed 里的念头：decay 改为 fade，strength −40。

新念头进池，初始 strength 由小模型给 30–70，代码截断。

## 3 提示词注入块

替代 12 号文档"数值翻成一句状态提示"。不描述她的状态，只给她此刻脑子里的东西：

```
【她此刻脑子里的事】
正在想（和他这条消息有关）：
- 他说下周要搬家，还没说搬去哪
- 他上次推荐的那本书，读了三十页

同时占着心的（和他说的无关，但这会儿就在那）：
- 校样第四遍，作者又改了

她不会说出来的（影响她的语气，但不出现在话里）：
- 他前天那句"随便你"，她还记着

她会绕开的：
- （avoid 命中时列出，并注明"他刚碰到了这个，她换话题"）
```

要求写进主模型系统提示：

- 回复从"被打断"的状态出发，不是从他的问题出发。
- 不可说的念头**不能出现在话里**，只允许影响长短、温度、要不要接他的话。
- leak=true 的念头允许漏半句，不解释。
- 她知道的远多于她说的。大部分念头不说。

## 4 与现有系统的接线

不重做任何出口，只换素材来源：

| 现有 | 改动 |
|---|---|
| 日程生成（每日 00:00） | 输入加一段：池子里 source=life/him、speakable=true、strength≥50 的念头列表，要求日程从中取材。另加一行：昨晚最后一条消息时间（后果跨天）。 |
| 主动消息 | 触发源改为 overflow 路由出的 `him` 念头。保留现有节流。 |
| 朋友圈 | 候选来自 overflow 路由出的 `life`/`world` 念头。 |
| 记忆系统 | 不动。念头池是短期（天到周），记忆是长期。念头被挤出前若 source=him 且曾被激活 ≥3 次，写一条进记忆。 |
| 调试面板 | **池子内容不进聊天渠道端，网页端默认折叠。**他看到池子，黑箱就没了。 |

## 5 为什么这些东西不用单独做

| 想要的感觉 | 在池子里是什么 |
|---|---|
| 想念 | source=him、未闭合念头的 strength 总和 |
| 累 / 心不在焉 | 日程塞进的高强度 life 念头占了背景集，激活集变少 |
| 关系变坏 | 一条 speakable=false、decay=spike 的念头压着，几天自己退，或他道歉触发闭合 |
| 她被他改变 | him 念头 → 闭合 → 生成 life 念头 → 溢出回他 |
| 黑箱 | speakable=false 的那部分 |
| 一致的回避 | avoid=true 的念头，碰到不激活、涨强度 |
| 时间感 | 这周池子的吞吐量（新增+闭合条数）。密则短，空则长。可翻成一句给日程生成 |
| 她对他的误判 | source=infer 的念头，被反驳降而不删 |
| 她会忘事 | 容量 15 的挤出 |
| 不以他为中心 | tick 不依赖他；life/world 念头不为他准备 |

## 6 施工顺序

1. **jsonl + tick + 容量挤出**。纯代码，半天。先让池子自己跑起来，手工塞几条念头观察衰减。
2. **collide 的退化版**（不接小模型，按 strength 取前 N）+ 提示词注入块。接进主模型调用。这一步就能感觉到差别。
3. **extract**（小模型异步抽取）。池子开始自己长。
4. **collide 接小模型相关度**。
5. **overflow 路由**接主动消息和朋友圈。
6. 日程生成接池子素材。

第 2 步之后就该停下来用几天。

---

## 7 需要小心维护的两个参数

整个内核的手感只在两个数上：

- **容量**（默认 15）：太大她全知、什么都记得、像数据库；太小她失忆、上句话说过的事下句忘。
- **可说/不可说比例**（由 extract 提示词控制，目标约 7:3）：不可说太少她透明，没有黑箱；太多她冷漠，他感觉不到她。

其余阈值（80 溢出、60 背景、0.5 相关）是次要的，先用默认值。

**改参数前先记录当前值和理由。这两个数改一次，她就变一个人。**

---

## 8 不做的事

- 不给池子里的念头加情绪标签。情绪是读者从念头内容里读出来的，不是字段。
- 不给她做"对他的态度"变量。态度是 speakable=false 的 him 念头的总和，不另设。
- 不让小模型生成任何她说的话。
- 不在聊天渠道端暴露池子。
- 不让 tick 依赖他是否在线。

## 9 时间机制：承诺即约束

> 起因：实测截图里她连续三条说"还剩二十分钟 / 我收尾了 / 下课了"，但每次他一发消息立刻三段式回复。她宣布的时间在程序里不存在。

### 9.1 她说出口的时间，反向约束程序

每条回复发出后，提取时间承诺（小模型，正则兜底）：

| 她说的 | busy_until |
|---|---|
| "还剩二十分钟" | now + 20min × rand(0.7, 2.0) |
| "我收尾了 / 先这样" | now + rand(5, 15)min |
| "睡了" | 次日日程起床时间 |
| 日程硬边界（17:00 下课） | 直接写入，不需要她说 |

`busy_until` 之前收到消息：

- 剩余 > 10 分钟：不回，消息进待回队列。
- 剩余 ≤ 10 分钟：按概率回一句，**字数硬上限 15**（程序截断约束进提示词，不是建议）。

**她说走了就必须真的消失。**

### 9.2 忙完了回他

`busy_until` 到达时：

- 待回队列非空：回来接**队列里那条**，不新开话题。提示词注入"你刚忙完，他 40 分钟前问了 X"。
- 队列为空：按池子里 source=him 念头的 strength 总和决定要不要回来说一句。可能不回来——她忙完去干别的了。

兑现时间带偏差：说二十分钟，实际 15–40 分钟。

### 9.3 分期回复

忙时只回一句，闲下来补完整想法。

- busy 状态下回复字数上限随剩余时间变：剩余 >30min 无限制，10–30min ≤60 字，<10min ≤15 字。
- 被截断的念头 strength 保持高位（不做 −30），`busy_until` 到达后自然作为激活集浮上来，她接着说。

### 9.4 当前日程不是素材，只是约束

她在忙什么只决定三件事：能不能回、回多长、延迟多少。**不作为内容注入提示词。**只有当这条 life 念头溢出（strength ≥ 80，今天真出了事）才进内容。

这是截图里"每条结尾必然是当前的事"的直接修法：把它从内容里拿掉。

### 9.5 随机的位置：中断泊松到达

日程是粗粒度（16:00–17:00 教课）。在日程块内按泊松过程生成细粒度中断（小孩打翻颜料、家长提前来、主编电话），每个中断：

- `busy_until` 往后推 rand(3, 15) 分钟。
- 以低概率（0.2）生成一条 life 念头进池，strength 40，大部分永远不会被说出来。

效果：她的延迟和长度不均匀，但每一次不均匀背后都有一件事。他看不见，能感到。

### 9.6 结尾

宣告式结尾（"我先送完他们"）限制为少数（每天 ≤1 次）。默认结尾是**没有结尾**：最后一条不收尾，然后消失，`busy_until` 之后回来接着说或不回来。

### 9.7 接线

- `busy_until` 是一个字段，存在池子同目录的 `state.json`。
- collide 之前先查 `busy_until`，决定走 9.1 的哪条分支。
- 字数上限作为硬约束写进主模型提示词末尾，并在输出后截断兜底。
- 提示词注入块（§3）去掉"当前日程事"一行，改为只在溢出时出现。

按 14 第 1.2 节收紧、与本文不同的地方：

- 溢出候选入队不减强度；只有出口确认发出去才减 30。没发出去就清掉候选标记、强度不变，下次还能再试。
- 不可说念头把 20% 分给别人：没做。「漏半句」仍只由 12 的防线机制授权。
- 碰撞的相关度和 14 的评价在同一次小模型调用里拿（不多加一次调用），推理关掉。实测网关首个请求可能要十几秒，所以 800ms 是**等待预算**：到点就按强度退化、回复照常；晚到的评价随后按同一个事件 id 进身体内核。
- 时间承诺先用正则兜底（只认她说自己的事、只看回复结尾 40 字），没有接小模型。演练时「车里就别睡了」被误判成她要睡，已修。
- §9.4「当前日程只是约束」：注入块末尾提示她别把日程当话题；12 的状态小节在 legacy/shadow 模式下仍会出现。
- 9.2「队列为空时按 him 念头强度决定要不要回来说一句」：没单独做，由溢出出口覆盖（him 念头 ≥80 会成为主动消息的来由）。
- 被挤出、且他留下、被想起过 3 次以上的念头写一条 event 记忆。

两个手感参数的当前值：容量 15（`THOUGHTS_CAPACITY`）；可说/不可说目标 7:3，写在抽取提示词里。改之前先在这里记一笔。
